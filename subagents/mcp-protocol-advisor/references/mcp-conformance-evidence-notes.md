# MCP Conformance — Evidence Notes

Evidence notes behind the highest-confidence MCP conformance principles. Each note ties a principle
to a sample of its backing claims and evidence records so a reviewer can trace a recommendation to
the distilled specification. Source: the Model Context Protocol specification (2024-11-05 through
2025-11-25); distillation-only.

## P001 — Build on the MCP base protocol: exchange JSON-RPC 2.0 messages over stateful connections and complete client/server capability negotiation before using any feature.

- `C00005`: MCP uses JSON-RPC 2.0 messages as its wire format to establish communication between participants.
- `C00008`: MCP connections are stateful, so implementations must maintain per-connection session state rather than treating each message as independent.

Evidence: E00005, E00008.

## P002 — Design MCP list operations that can return large result sets (resources/list, resources/templates/list, prompts/list, tools/list) to support cursor-based pagination, yielding results in smaller…

- `C00447`: To retrieve available prompts, a client sends a `prompts/list` request, and this operation supports pagination via a cursor.
- `C00448`: A `prompts/list` response returns a `prompts` array and an optional `nextCursor` for paginating to the next page of results.

Evidence: E00438, E00439.

## P003 — Require explicit user approval of every LLM sampling request, let users control whether sampling occurs, the exact prompt sent, and what results the server may see, and limit server visibility into…

- `C00028`: Users must explicitly approve any LLM sampling request before it is executed.
- `C00029`: Users should be able to control whether sampling occurs at all, the actual prompt that will be sent, and what results the server is allowed to see.

Evidence: E00028, E00029.

## P004 — Handle JSON Schema dialects explicitly: default to 2020-12 when no $schema is declared, allow a $schema field to select another dialect, support at least 2020-12 while documenting any additional…

- `C00090`: When a schema omits a $schema field, implementations MUST treat it as JSON Schema 2020-12 (the default dialect).
- `C00091`: A schema MAY include a $schema field to declare a dialect other than the default.

Evidence: E00089, E00090.

## P005 — Route all server-originated LLM access through the client via sampling: let the client own model access, selection, and permissions so servers need no API keys of their own.

- `C00052`: Servers request sampling through the client interface rather than directly.
- `C00395`: MCP sampling provides a standardized way for servers to request LLM completions from language models via the client, so the client retains control over model access, selection, and permissions and servers need no API keys of their own.

Evidence: E00051, E00388.

## P006 — For task-augmented requests, keep using the original request's progressToken for the entire task lifetime — including after CreateTaskResult is returned — and never switch tokens mid-task; the token…

- `C00237`: For a task-augmented request, the progressToken from the original request must keep being used for progress notifications throughout the task's lifetime, including after the CreateTaskResult has been returned.
- `C00238`: A task's progressToken remains valid and bound to the task until the task reaches a terminal status.

Evidence: E00235, E00236.

## P007 — Treat tool annotations as untrusted input: a client must not rely on tool annotations for security decisions unless they come from a trusted server.

- `C00025`: Descriptions of tool behaviour, such as annotations, should be treated as untrusted unless they come from a server the user already trusts.
- `C00512`: Clients must treat tool annotations as untrusted unless they come from trusted servers.

Evidence: E00025, E00503.
