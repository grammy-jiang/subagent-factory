# Write the four documentation types

## Purpose

Once a page's Diátaxis type is settled, write it in the register that type demands. Each of the
four forms serves a different need, so each is written differently; the most common failure is
letting a form drift into a neighbouring one. This skill gives the working rules for tutorials,
how-to guides, reference, and explanation.

## When to use

- A page's type is known (via `classify-with-the-diataxis-compass`) and it must be drafted or
  rewritten in the right register.
- A reviewer must check whether a page reads as its declared type.
- A form has drifted — a reference is teaching, a how-to is explaining — and needs pulling back.

Do not use this skill to decide the type; classify first.

## Procedure

### Tutorials — a lesson the learner learns by doing (P004)

1. **Frame a meaningful, achievable goal** the learner reaches by doing, and show them where they
   are going from the start. (P004, P028)

2. **Follow the first rule of teaching: don't try to teach.** Ruthlessly minimise explanation;
   give the minimum needed to act, and link out for the rest. (P009)

3. **Hold the lesson to high construction standards**: every exercise meaningful, completable,
   and logically ordered, so the learner always succeeds. (P028)

### How-to guides — a recipe for a competent user's real goal (P019)

4. **Define the guide by a specific real-world goal or problem** for a user who is already
   competent — not by teaching them. (P019)

5. **Order the steps as a meaningful sequence in time**, imposing order only where necessity
   dictates. (P039)

6. **Exclude teaching, explanation, and reference completeness** — link out to them; keep the
   guide focused on reaching the goal. (P053)

### Reference — austere, product-led description (P002)

7. **Describe and only describe.** Resist instruction, explanation, and opinion; link out
   instead. (P002)

8. **Let the product lead the structure** — mirror the machinery, adopt consistent standard
   patterns placed where users expect, and state facts, lists, and warnings plainly. (P002)

9. **Keep examples illustrative**, not lessons; an example must not slide into explanation.
   (P002)

### Explanation — bounded, understanding-oriented discussion (P005)

10. **Anchor the explanation to a real or imagined "why" question** and stay within its bounds;
    do not let it sprawl into reference detail or step-by-step instruction. (P005)

11. **Make connections** — to other ideas, alternatives, and background — so the reader
    understands, rather than instructing them to act. (P005)

### Across all four — keep the forms distinct

12. **Watch the boundaries.** When drafting or reviewing, name any sentence that belongs to a
    neighbouring form and move it to the page of that type. The forms and their purposes must
    never muddle together. (P008)

## Inputs

- **Required:** the page's settled Diátaxis type, its goal, and its audience.
- **Optional:** an existing draft to rewrite in register.

## Output

A draft or rewrite in the correct register for the type, or — in review — a list of sentences
that have drifted out of the type with the correction for each.
