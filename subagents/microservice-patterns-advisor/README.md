# microservice-patterns-advisor

A generated Claude Code subagent that advises on **microservice pattern
selection**. Given a microservice architecture concern, it names the applicable
patterns from the microservices pattern language, explains the forces each
pattern resolves and its trade-offs, and recommends a fitting choice. It does
not write code, choose products, or own the architecture decision.

## What it does

- **advise** — Given a microservice architecture problem, recommend which
  pattern(s) apply and why, tied to the caller's forces.
- **compare** — Contrast two or more patterns that address the same concern
  (e.g. Saga vs. distributed transaction; Database per service vs. Shared
  database; Messaging vs. Remote procedure invocation).

## When to use it

- Deciding how to decompose an application into services (and whether to adopt
  microservices at all).
- Maintaining data consistency across services with sagas, or querying data that
  spans services (API composition vs. CQRS).
- Choosing an inter-service communication, discovery, external-API, or
  reliability style; publishing events reliably.
- Selecting business-logic, testing, production-readiness, or deployment
  patterns, or migrating a monolith incrementally.

## When not to use it

- You want a pattern implemented or configured in a specific language /
  framework / product (the book's Java/Spring examples are out of scope here).
- You want a concrete technology, vendor, or product chosen.
- The concern is outside microservice architecture.
