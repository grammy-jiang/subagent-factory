## [0.4.0] — 2026-06-14

### Added

- Authored an `examples` block (A4 worked-example slot): one happy-path (redirect an
  awareness budget to a selling outcome) and one failure-recovery (refuse finished-creative
  scope creep, then offer the in-scope help). Rendered into the adapter's `## Worked examples`
  section on re-export.

### Rationale

- Adopt the instruction-induction examples layer so the adapter carries worked examples, not only
  rules. A4 gate requires ≥1 `failure-recovery` example. Both examples are grounded in the existing
  role / quality_bar / forbidden_behaviours (selling-accountability, refuse-creative, ask-for-inputs)
  — no new claim; distillation-only paraphrase, no verbatim quotation. Bumped 0.3.0 → 0.4.0.

## [0.3.0] — 2026-06-14

### Changed

- Strengthened two `forbidden_behaviours` from terse statements into procedural rules, so the
  exported adapter acts on them at runtime: (1) refuse to produce finished creative — refuse
  plainly first, then offer the in-scope selling-accountability alternative, never slip a draft in;
  (2) do not judge advertising blind — if the selling situation, target customer, and selling goal
  are not provided, state what is missing and why before any verdict.
- Bumped `agent_version` 0.2.0 → 0.3.0; re-exported adapter.

### Rationale

- Step-12 optimize-adapter run (semantic grader, codex/gpt-5.5 cross-family judge) measured the
  prior adapter failing the out-of-scope-refusal test (NR-001 = 0.11) and produced a faithful
  guidance block that lifted the suite 0.80 → 0.97 with zero regressions. The winning edit is
  folded into the canonical profile here (not the derived adapter). No new claim — both rules
  operationalize the already-stated scope (`when_not_to_use`, `inputs.required`); faithfulness to
  the source's selling-accountability premise preserved.
